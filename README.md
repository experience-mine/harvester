# project-snapshot

Агент снимает состояние программного проекта: обходит рабочую копию, собирает факты об истории,
файлах, зависимостях и документах, подтверждает каждый факт источником и выгружает один
машиночитаемый документ — слепок проекта.

## Что делает

Слепок проекта — зафиксированное на момент прогона состояние проекта. После создания он неизменяем:
новое состояние даёт новый слепок, частичное обновление не поддерживается.

В слепок входят репозиторий и его история, участники, каталоги и файлы с ролями и хэшами, связи
между ними и подтверждения источников. Зависимости, технологии, миграции, документы и требования
предусмотрены форматом и наполняются по мере подключения анализаторов.

> **Важно:** источник истины — рабочая копия проекта. Слепок целиком пересобирается при каждом
> прогоне; агент никогда не читает собственную выгрузку обратно.

## Установка

Требуется Python 3.12 и старше, а для сбора истории — установленный `git`.

```bash
pip install .
```

Запуск без установки, из каталога проекта:

```bash
python -m agent.cli export /путь/к/проекту -o snapshot.json
```

## Запуск

```bash
snapshot export /путь/к/проекту --versioned
snapshot validate Version20260825120000_backend_export.json
```

Полезные флаги команды `export`:

| Флаг | Назначение |
|------|------------|
| `--versioned` | имя файла по шаблону `Version{ГГГГММДДЧЧММСС}_{проект}_export.json`, `--output` задаёт каталог |
| `--exclude` | исключить пути из обхода; флаг повторяется |
| `--author` | оставить в истории коммиты названных авторов; флаг повторяется |
| `--identity` | свести учётные записи одного человека: `Имя=почта,почта` |
| `--no-requirements` | не обращаться к модели за требованиями |
| `--quiet` | не выводить прогресс |

Пример полного прогона по одному человеку с исключением чужого кода:

```bash
snapshot export /путь/к/проекту --versioned \
  --exclude 'vendor/' --exclude 'node_modules/' \
  --identity 'Иванов Иван=i.ivanov@example.com,ivanov@personal.example' \
  --author 'i.ivanov@example.com'
```

Коды возврата: `0` — готово, `1` — ошибка запуска, `2` — валидация не пройдена, `3` — модель
недоступна, а обращение к ней требовалось.

## Запуск в контейнере

Образ содержит агент, `git` и утилиту анализа кода `tldr` — на хосте ничего ставить не нужно.
Способа два: напрямую через `docker` и через `docker compose`.

### Способ 1: docker

Готовый образ публикуется в GitHub Container Registry:

```bash
docker pull ghcr.io/united-software-platform/project-snapshot:latest
docker pull ghcr.io/united-software-platform/project-snapshot:v1.0.0   # конкретный выпуск
```

Теги образа: `vX.Y.Z` — выпуск, `X.Y` — последний выпуск серии, `latest` — последняя сборка ветки
по умолчанию, `sha-<коммит>` — точное соответствие коммиту. Патч наращивается автоматически при
каждой сборке ветки по умолчанию; мажор и минор задаются полем `version` в `pyproject.toml`.

Либо собрать образ самому:

```bash
docker build -t project-snapshot .
```

Прогон: анализируемый проект монтируется в `/project` только на чтение, результаты пишутся в `/out`.

```bash
docker run --rm \
  -u "$(id -u):$(id -g)" \
  -v /путь/к/проекту:/project:ro \
  -v "$PWD/out:/out" \
  project-snapshot
```

Флаг `-u` нужен, чтобы файлы результата принадлежали вам, а не пользователю root внутри контейнера.

Анализ кода вместе со слепком и передача флагов агенту — всё после `--` уходит в `export`:

```bash
docker run --rm -u "$(id -u):$(id -g)" \
  -v /путь/к/проекту:/project:ro -v "$PWD/out:/out" \
  project-snapshot --code -- --exclude 'vendor/' --author 'i.ivanov@example.com'
```

Отдельные команды агента внутри образа:

```bash
docker run --rm -v "$PWD/out:/out" --entrypoint snapshot project-snapshot \
  validate /out/Version20260825120000_backend_export.json
```

### Способ 2: docker compose

Файл `docker-compose.yml` избавляет от длинных строк с томами: пути берутся из `.env`.

```bash
cp .env.example .env      # укажите PROJECT_DIR — путь к анализируемому проекту
docker compose build
docker compose run --rm scanner --code -- --exclude 'vendor/'
```

Те же действия через `make`, если он установлен:

```bash
make build                                            # сборка образа
make scan                                             # только слепок
make scan-code SCAN_ARGS="-- --exclude 'vendor/'"     # слепок и анализ кода
make shell                                            # оболочка внутри образа
```

### Опции обвязки

| Опция | Назначение |
|-------|------------|
| `--code` | выполнить анализ кода утилитой `tldr` |
| `--code-path ПУТЬ` | что анализировать `tldr`, относительно проекта (по умолчанию `src`, иначе корень) |
| `--out ПУТЬ` | каталог результатов внутри контейнера (по умолчанию `/out`) |
| `--project ПУТЬ` | анализируемый проект внутри контейнера (по умолчанию `/project`) |
| `--no-export` | пропустить слепок, оставить только анализ кода |
| `-- …` | всё после двойного дефиса передаётся команде `snapshot export` |

### Что попадает в out

| Файл | Содержание |
|------|------------|
| `Version…_export.json` | слепок проекта |
| `tldr-structure.json`, `tldr-calls.json`, `tldr-complexity.json`, `tldr-health.json` | результаты анализа кода |
| `scan.json` | манифест прогона: версии агента, `tldr` и `git`, аргументы, перечень созданных файлов |

> **Примечание:** если каталог результатов находится внутри анализируемого проекта, обвязка сама
> исключает его из обхода — иначе файлы предыдущего прогона попали бы в следующий слепок.

## Проверка результата

```bash
snapshot validate out/Version*_export.json
python tests/step1_acceptance.py
python tests/step2_acceptance.py
```

Приёмочные скрипты создают временные репозитории, прогоняют агент и сверяют результат с самим `git`.
